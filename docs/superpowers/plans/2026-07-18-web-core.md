# Web 应用核心实现计划（MVP 子计划 1/3）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 搭建 Remote Reader 的 Web 应用核心——能通过 Token 认证的 API 上传 md 文档，并在浏览器通过分享链接一步查看渲染结果。

**Architecture:** SvelteKit 全栈单实例应用 + SQLite(Drizzle ORM) + 本地文件存储。上传 API 用 Token 认证，查看页用 share token 免登录。monorepo(Bun workspaces) 中 `apps/web` + `packages/shared`。

**Tech Stack:** TypeScript, Bun(包管理+dev/build 宿主), SvelteKit, Drizzle ORM(better-sqlite3), markdown-it, Shiki, @node-rs/argon2(argon2id), vitest(node 跑测试)

**本计划不包含：** 本地 MCP 桥（子计划 2）、文件管理器 UI（删除/移动/重命名）、**分享链接撤销管理页**与 Docker（子计划 3）。spec §6.4 的"owner 可撤销查看链接"推迟到子计划 3 的分享管理页；本子计划只**生成** share token，不做撤销 UI。

**TDD 约定：** 纯逻辑模块用 vitest 做 TDD（先写失败测试→实现→通过→commit）：`bun run test`（node 运行时，详见下方「测试与运行时约定」）。SvelteKit endpoints/pages 用 curl/浏览器做集成验证。5 个标 `[开放决策点]` 的步骤按 learning 模式留给用户亲手实现（提供签名+引导，不写死）。

**SvelteKit 2 用法约定（重要）：** `error()` 与 `redirect()` **自身会 throw**（返回 `never`）。直接裸调用 `error(...)` / `redirect(...)` 即可生效——写 `throw error(...)` 或 `return error(...)` 虽也能工作但属冗余。**禁止把它们放进 try/catch**（会被捕获导致失效）。实现时统一用裸调用。

**Vite SSR 禁 Bun API（关键约束）：** `apps/web` 所有服务端代码（`src/lib/server/**`、`hooks.server.ts`、routes 的 `*.server.ts`、`+server.ts`）在 Vite 驱动的 SSR 下运行，**Vite 不识别 Bun 专属模块/全局**（`bun:sqlite`、`Bun.*` 等），导入会在 SSR/构建期失败。一律用 node 兼容替代：DB 用 `better-sqlite3` + `drizzle-orm/better-sqlite3`（Task 4），密码哈希用 `@node-rs/argon2`（Task 5），其余哈希/随机用 `node:crypto`。`Buffer`、`crypto`（webcrypto 全局）可用。

**测试与运行时约定（重要，已验证）：** `better-sqlite3` 是 C++ 原生 addon，**Bun 直接运行时（`bun -e`/`bun run script.ts`/`bun test`）加载它失败**（oven-sh/bun#4290），但 `bun + vite dev` 下能加载（vite 的模块加载路径不同）。反之 `bun:sqlite` 又被 Vite SSR 拒绝。因此本项目的运行时分工：
- **包管理/构建/dev**：`bun install` / `bun --filter ... build` / `bun --filter ... dev`（均 OK）。
- **测试**：用 **vitest**（`bun run test`），由 vitest bin 的 node shebang 在 **node** 下执行——node 能正常加载 better-sqlite3。测试文件 `import { test, expect, ... } from 'vitest'`。配置在根 `vitest.config.ts`。
- **生产**：adapter-node 产物用 **`node build/handler.js`** 启动（不要 `bun run build/handler.js`，会触发 better-sqlite3 加载失败）。
- 结论：dev/test/prod 任何碰 DB 的路径都在 node 兼容运行时下；bun 仅作包管理器与 vite 宿主。

## Task 2: 路径 sanitize 与解析 [开放决策点 1]

**Files:**
- Create: `packages/shared/src/paths.ts`
- Test: `packages/shared/src/paths.test.ts`

**为什么留给你写：** 路径 sanitize 是安全关键点（防路径穿越），且有多种合理策略（如何处理 `..`、空段、非法字符、嵌套创建策略）。你的选择决定安全边界。

**引导：**
- 输入：用户/Agent 传的 POSIX 风格路径字符串，如 `"reports/2026-07/weekly.md"` 或仅 `"weekly.md"`
- 需要拒绝：`..` 段、绝对路径（`/`开头）、空字符串、含 null byte、Windows 非法字符
- 需要输出：干净的段数组，如 `["reports","2026-07","weekly.md"]`，用于后续拼接 `data/documents/<uid>/<...>/<name>`

- [ ] **Step 1: 先写失败测试（你决定具体规则，至少覆盖这些 case）**

- [ ] **Step 3: 写 `apps/web/src/lib/server/db/index.ts`（better-sqlite3）**

> ⚠️ **不要用 `bun:sqlite`**：见顶部「Vite SSR 禁 Bun API」约束。改用 node 兼容的 `better-sqlite3` + `drizzle-orm/better-sqlite3`。

```ts
import Database from 'better-sqlite3';
import { drizzle } from 'drizzle-orm/better-sqlite3';
import { existsSync, mkdirSync } from 'node:fs';
import { dirname } from 'node:path';
import * as schema from './schema';

const dbPath = process.env.DATABASE_PATH ?? './data/app.db';
const dir = dirname(dbPath);
if (!existsSync(dir)) mkdirSync(dir, { recursive: true });

const sqlite = new Database(dbPath);
sqlite.pragma('journal_mode = WAL');

export const db = drizzle(sqlite, { schema });
export { schema };
```

```ts
import { createHash, randomUUID } from 'node:crypto';
import { hash as argon2Hash, verify as argon2Verify } from '@node-rs/argon2';

const ARGON2ID = 2;

export async function hashPassword(password: string): Promise<string> {
    return argon2Hash(password, { algorithm: ARGON2ID });
}

export async function verifyPassword(password: string, hashStr: string): Promise<boolean> {
    return argon2Verify(hashStr, password);
}

export function generateId(): string {
    return randomUUID() + Date.now().toString(36);
}

export function sha256Hex(input: string): string {
    return createHash('sha256').update(input, 'utf8').digest('hex');
}
```

> 注：`@node-rs/argon2` 的 `verify(hash, password)` 参数顺序——哈希在前、明文在后。`node:crypto` 的 `createHash`/`randomUUID` 同步且跨运行时；**不要用 `crypto.subtle.digestSync`**（Deno/Cloudflare Workers 扩展，Node/Bun 无此 API）。
> **argon2 const enum 陷阱**：`@node-rs/argon2` 把 `Algorithm` 声明为 `const enum`，SvelteKit 生成的 `verbatimModuleSyntax`+`isolatedModules`（后者是 vite 必需、不能关）会报 `Cannot access ambient const enums`。故**用字面量 `ARGON2ID = 2`**（=Argon2id 标准编码，argon2: Argon2d=0/Argon2i=1/Argon2id=2），不导入枚举；同时在 `apps/web/tsconfig.json` 关 `verbatimModuleSyntax`（仅影响 svelte-check 严格度，不影响 vite build）。另需补 `@types/node` + `@types/better-sqlite3`（devDep）否则 svelte-check 报 node/better-sqlite3 无类型。

```ts
import { sha256Hex } from './auth';

const SECRET = process.env.SESSION_SECRET ?? 'dev-insecure-secret';

export function sign(payload: object): string {
  const body = Buffer.from(JSON.stringify(payload)).toString('base64url');
  const sig = sha256Hex(body + '.' + SECRET);
  return `${body}.${sig}`;
}

export function verify(token: string): { userId: string } | null {
  const [body, sig] = token.split('.');
  if (!body || !sig) return null;
  const expected = sha256Hex(body + '.' + SECRET);
  if (expected !== sig) return null;
  try {
    return JSON.parse(Buffer.from(body, 'base64url').toString('utf-8'));
  } catch {
    return null;
  }
}
```

## Task 11: 文档上传 + content_hash 幂等 [开放决策点 2]

**Files:**

- Test: `apps/web/tests/documents.test.ts`

**为什么留给你写：** 幂等判定（"同路径已有文档时，何时覆盖、何时跳过"）是核心业务逻辑，有多种合理策略（按 path+name 定位、按 hash 判断内容是否变化、是否级联创建父文件夹）。你定调。

- 输入：`ownerId`, `name`(如 `weekly.md`), `content`(md 文本), `pathSegments`(来自 Task 2 的 `parsePath`，**不含**文件名本身，如 `["reports","2026-07"]`)

  2. 算 `contentHash = sha256(content)`
  3. 在目标文件夹下找同名 file 文档：

```ts
import { db, schema } from './db';
import { hashToken } from './auth';
import { eq } from 'drizzle-orm';

export function authenticateApiToken(authHeader: string | null): { userId: string; tokenId: string } | null {
  if (!authHeader?.startsWith('Bearer ')) return null;
  const plaintext = authHeader.slice('Bearer '.length).trim();
  // join users：确保 token 指向的用户仍存在（防 token 残留指向已删用户）
  const row = db.select({ token: schema.apiTokens, user: schema.users })
    .from(schema.apiTokens)
    .innerJoin(schema.users, eq(schema.apiTokens.userId, schema.users.id))
    .where(eq(schema.apiTokens.tokenHash, hashToken(plaintext))).get();
  if (!row) return null;
  db.update(schema.apiTokens).set({ lastUsedAt: Date.now() })
    .where(eq(schema.apiTokens.id, row.token.id)).run();
  return { userId: row.user.id, tokenId: row.token.id };
}
```

- [ ] **Step 2: 写速率限制器 `apps/web/src/lib/server/ratelimit.ts`**

```ts
const buckets = new Map<string, { count: number; resetAt: number }>();

export interface RateLimitConfig {
  max: number;
  windowMs: number;
}

export function checkRateLimit(key: string, cfg: RateLimitConfig): { allowed: boolean; remaining: number } {
  const now = Date.now();
  const b = buckets.get(key);
  if (!b || b.resetAt < now) {
    buckets.set(key, { count: 1, resetAt: now + cfg.windowMs });
    return { allowed: true, remaining: cfg.max - 1 };
  }
  if (b.count >= cfg.max) return { allowed: false, remaining: 0 };
  b.count++;
  return { allowed: true, remaining: cfg.max - b.count };
}
```

```ts
import { json, error } from '@sveltejs/kit';
import type { RequestHandler } from './$types';
import { authenticateApiToken } from '$server/apitoken-auth';
import { checkRateLimit } from '$server/ratelimit';
import { uploadDocument } from '$server/documents';
import { parsePath } from '@remote-reader/shared/paths';

const MAX_BYTES = Number(process.env.MAX_UPLOAD_BYTES ?? 5 * 1024 * 1024);

// [开放决策点 4] 速率限制阈值，默认 60 次/分钟，可经 env 覆盖
const RATE_LIMIT = {
  max: Number(process.env.RATE_LIMIT_MAX ?? 60),
  windowMs: Number(process.env.RATE_LIMIT_WINDOW_MS ?? 60_000)
};

export const POST: RequestHandler = async ({ request }) => {
  const auth = authenticateApiToken(request.headers.get('authorization'));
  if (!auth) throw error(401, 'invalid or missing api token');

  const rl = checkRateLimit(`upload:${auth.tokenId}`, RATE_LIMIT);
  if (!rl.allowed) throw error(429, 'rate limit exceeded');

  let body: { name?: string; content?: string; path?: string };
  try { body = await request.json(); }
  catch { throw error(400, 'invalid json'); }

  const { name, content, path } = body;
  if (!name || typeof content !== 'string') throw error(400, 'name and content required');
  if (Buffer.byteLength(content) > MAX_BYTES) throw error(413, 'document too large');

  const segments = path ? parsePath(path) : [];
  const result = await uploadDocument(auth.userId, name, content, segments);
  return json(result);
};
```
